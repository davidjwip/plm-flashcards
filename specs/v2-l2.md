# v3 — Level 2 clusters, search, and the L2 chip

Status: **draft — awaiting Dave's approval.** Owner: Dave approves; agent drafts.
Non-goals are as binding as goals.

## 1. Problem

PLM Level 2 is not only single letters and vowels: the class also works on starting
clusters (`sm`, `bl`, `pl`, `sn` …), ending clusters (`nd`, `nt`, `nk`, `mp`, `st`, `ll`,
`ss` …), and `ar`/`or` in the middle of words. The bank has the vowels, the r-controlled
vowels and the Level 3 digraphs already, but **not one cluster tag** — so the app cannot
offer that work at all. With 46 cluster patterns added the pattern list reaches ~90 rows,
which is unusable as a flat checklist, and there is no single action for "practise
everything George is doing at Level 2".

## 2. Behaviour

| B3  | Every word has a committed mp3 in `en-GB-SoniaNeural`; no runtime or browser speech for these sets.  |

| B7  | Level 3 digraphs stay available but out of the L2 chip, except `ch`, `sh`, `th`, `ck`, which are in. |
| B8  | Nothing regresses: one-screen landing, fixed word frame, verdicts, party track, bee dictation.       |

## 4. Word and tag requirements

- **10 words minimum per pattern.** Today the 46 new patterns hold 0–23 words each; the
  shortfall to 10 is **264 pattern-slots**, which a curated list collapses to roughly
  **170–200 unique new words** because one word can serve several clusters
  (`stamp` = `st-` + `-mp`, `clamp` = `cl-` + `-mp`, `blend` = `bl-` + `-nd`).
- **Tags are generated from spelling by position**, then reviewed:
  - `X-` matches a word starting with `X` and longer than `X` + one letter;
  - `-X` matches a word ending with `X` and longer than `X` + one letter;
  - a word carries **every** cluster it demonstrates, plus its vowel/r-controlled tags;
  - `ck`, `ng`, `ll`, `ss` are never produced as side effects of a cluster rule — they are
    their own patterns.
- **Existing thin patterns are topped up too**: `-st` (9), `-lt` (7), `-ld` (6) and the
  rest must each reach 10, not just the new ones.
- The bank validator's minimum rises from "≥1 word" to "**≥10 words**", so a thin set fails
  CI instead of quietly shipping.

## 5. Audio requirements

- Every word in the bank **and** in the bee deck gets an mp3 from
  `scripts/generate-audio.py`: `en-GB-SoniaNeural`, rate −8%, mono 22.05 kHz, 64 kbps,
  loudness −14 LUFS.
- The generator currently reads only `data/wordbank.json`; it must also cover
  `data/bee.json` so bee words are never spoken by the browser.
- New words are not merged until their audio is committed — a word without a file is a
  word that speaks in whatever voice the tablet has, which is exactly what Dave ruled out.
- `audio-manifest.json` (and the app's `hasFile` check) must list every word.

## 6. Search and grouping

- The panel groups rows: **Short vowels · Starting clusters · Ending clusters ·
  R-controlled · Long vowels · Digraphs**. Groups collapse; the open ones remember state.
- A search field filters as you type, on label **or** id (`sm`, "start", "short a").
  - Selection survives filtering — a ticked row that is filtered out stays ticked.
  - The header pill keeps showing the true selected count.
  - No match shows "no patterns match …", not an empty box.
  - Clearing the field restores the full grouped list; focus lands in the field when the
    panel opens.

## 7. Bee Level 2

- In bee mode the header chip reads **Level 2** instead of the pattern count.
- Pressed, it restricts the deck to words containing at least one selected L2 pattern, and
  the count line says how many words that leaves.
- The same generated tags feed both modes; bee words are tagged at build time from their
  spelling, so `data/bee.json` does not need hand-maintained pattern lists.

## 11. Decisions

| #   | Decision                                           | Alternative rejected                                                                               |
| --- | -------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| D1  | one pattern per cluster, position in the id        | family-only tags — Dave wants "this week it's `sm` and `sn`"                                       |
